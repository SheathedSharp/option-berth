This chapter takes one checkout from nothing to a running stack and back to a clean stop. The example is Hello Worktree: two Python 3 processes, no package installs, no accounts and no API keys.

Before you start

You need oberth on your PATH (Install oberth), Python 3, and the example directory, which ships in the repository.

The checkout has to live under your home directory unless you pass --allow-outside-home. By default the engine refuses to manage a stack outside that boundary.

Declare the stack

The example already ships an oberth.yaml. Read it before you run anything, because it is the whole input.

Two services. api asks for an automatic port and a health check. worker has no port, starts after api, and receives the API's real address through ${api.url}. None of this is inferred from a running process.

In your own project, oberth init writes this file. An agent can propose one with oberth init draft; only a person runs oberth init adopt.

Start it and wait

--wait returns only when every service is really there: api has a bound listener and a passing /health, and the portless worker process is alive. A process that is still booting is not ready, and a timeout is not success.

Read what is running

The port belongs to this checkout. Another worktree of the same repository gets a different one, because port: auto is assigned per run rather than remembered per project. no port is a fact, not a failure: the worker is observed through its run record.

Open the address that status prints, and the API answers on the port it actually bound. The same read in JSON is oberth status --json --brief, which is what an agent opens with.

Read the worker's log

--once reads the current run's log and returns. Without it, logs keeps following. When a service has already failed, --first-error gives you the first error of the current run instead of the last screen of output.

Stop it

down stops the services this worktree started and hands their port reservations back. It does not touch another checkout, a normal user daemon, or a process the manifest never declared.

See the isolation for yourself

Create a second Git worktree of the same repository, enter examples/hello-worktree in both, and run up in each. The two API services get different ports. Run down in one, and the other keeps running.

This is not a container or an operating-system sandbox. It is isolation of run ownership and lifecycle: a run belongs to the checkout that started it. Several worktrees at once explains the rules, and down explains what a stop may never reach.
