down stops the services this worktree's manifest declares. It never crosses into another checkout, and it returns a port: auto reservation only after the stop is confirmed.

The normal stop

With no argument, down uses the nearest manifest. It stops the project's services and returns the port: auto reservations once the action confirms they can be released. --force uses a forced signal directly; it does not skip the run-identity or reservation-release gates.

When the checkout is gone

--worktree PATH stops by checkout root path, and --identity wt_… stops by identity. Neither can be combined with a project name or a manifest path. worktrees --gone lists the identities whose checkout no longer exists, so you can find the services and data a deleted checkout left behind.

An identity the daemon has never seen returns not_found; it does not guess a group. When the target already has no runs or reservations, an explicit identity is still a successful empty stop.

When the target is ambiguous

Two checkouts can really take the same group name, for example two same-named directories under different parents. Their groups are already merged, so a group-scoped stop would hit both; down returns ambiguous instead of picking one for the caller. Name the process by port or pid with kill.

What down never touches

  • machine: dependencies. Their listener state is read-only; down does not stop them.
  • Another worktree's services. A stop by project name is group-scoped, and the other checkout's group is a different name.
  • Your data. The engine reports identities and stops services; deleting a database or data directory is a person's decision.
  • Signals already sent are not undone by an error. An incomplete stop, a failed observation or a refreshed reservation keeps the reservation and returns the error.
