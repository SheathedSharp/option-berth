Every fact starts with a declaration. oberth.yaml says what this checkout runs; a person confirms it, and the engine never infers a start command from a process it happened to see.

Start from the worktree

oberth init generates a starter manifest from the current checkout, in a form you can review. Listening ports and declarations found in project files appear only as comments, for a person to decide on. A failed listener scan does not abort init: the comment says listening unknown with the observation code and the next step, because “could not look” is not “nothing is listening”.

--dry-run previews without writing, and --json gives the machine shape. Even when the scan fails, the project's own declarations and an entry shape to copy are still there.

Let an agent draft, a person adopt

init draft [agent] asks the configured local agent for a manifest. option-berth judges nothing, goes online for nothing and writes nothing: a successful run only produces a draft, archived by default under ~/.option-berth/drafts/. init adopt is the step that writes oberth.yaml. An existing manifest needs an explicit --replace or --merge, and --dry-run with --diff shows the result first. A draft is not authorization.

The smallest manifest

The fields in the smallest manifest
FieldWhat it promises
nameThe project group. Two worktrees of the same repository publish as name and name@worktree.
services[].cmdThe long-running command, split into argv without a hidden shell.
portA fixed number, or auto so the engine allocates one per run and injects PORT.
healthAn HTTP path, a TCP port or a command. A service that opens its port before its protocol is ready uses the command form.
depends_onStart order and readiness waiting: a dependent starts only after its dependency is ready.
envLiteral values, and references such as ${api.url} that expand from this worktree's address book.

Fields that change behavior

prepare: and prepare_inputs:
A prerequisite command that runs before the long-running cmd:. When the declared inputs have not changed since the last success, the next up skips it instead of reinstalling dependencies.
sources:
The files that tell whether the process is running the current code. status publishes code_changed_since_start when they have changed; sources: [] turns the check off for a service that hot-reloads.
ready_timeout:
The service's own readiness budget, as a Go duration, 30s by default. Successors and up --wait use it, and prepare: does not count against it.
env_file:
A dotenv-style file, read at start and never written back. Relative paths resolve from the manifest directory, so several worktrees can share one file outside the checkout.
machine:
A dependency this project observes but never starts or stops: a database, middleware, a service someone else owns.
workspace:
An address reference to a service in another checkout. It supplies ${name.url} and takes no part in start, stop or depends_on.

What the manifest may not do

  • Unknown keys are ignored by default. BERTH_STRICT_MANIFEST=1 turns them into load errors with line and column positions, and the published schema rejects them too.
  • One YAML document only. A second document, or the same service declaring port twice, is an error with a line number.
  • A reference has one of five shapes: the service's own ${port} or ${url}, another service's address, a machine: or workspace: address, and ${worktree}. Any other ${...} stays text.
  • machine: and workspace: are read-only. up, down and restart never start or stop the other side.
  • An agent's draft never writes oberth.yaml. Only a person's init adopt does.
