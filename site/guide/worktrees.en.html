A run belongs to the checkout that started it. Two worktrees can run the same repository at once without sharing a port, a database or a stop.

A run belongs to its checkout

Different worktrees of one repository publish as <project> and <project>@<worktree>, so a group-scoped stop on one does not reach the other. status --json publishes the checkout's identity, and down --identity uses that identity after the directory is gone.

Ports are allocated, not guessed

A service with port: auto gets its address from the run, and the engine injects it through PORT. If the service sets env: PORT: 3000 itself, that value overrides the injected one and up --wait waits on the wrong port; use ${port} instead. If a framework quietly moves to another port when one is taken, turn on its strict-port option so the conflict becomes a readable failure.

Data can follow the worktree

${worktree} is a stable identity derived from the canonicalized checkout root. It stays the same on every start of one worktree, and differs between the main checkout and each linked worktree, which makes it suitable for database names and relative data directories.

Move the checkout directory and you get a new identity; the old data does not move with it. That is deliberate: the engine reports the correspondence between identities and paths, and a person decides what to keep.

When a checkout disappears

worktrees --gone keeps only the identities whose checkout no longer exists. down --identity still stops the runs and listeners that belong to one and returns its port: auto reservations. The engine only reports and stops; it never deletes a database, a data directory or a ledger row.

Follow changes without polling

oberth events is the read-only subscription for parallel work. It takes a worktree, repository or explicit workspace filter and writes NDJSON: the first line is a state.snapshot, and later lines are state.changed summaries.

  • The first record is a snapshot and later records are changes. After a dropped connection, pass the last applied seq as after_seq.
  • Only runtime fact summaries cross the stream. Logs, commands, working directories and environment variables do not.
  • When the queue window has expired or the state chain is discontinuous, the stream returns a full snapshot instead of pretending the gap did not happen.
  • --once reads the snapshot only and registers no workspace membership; a person running it is usually troubleshooting.
