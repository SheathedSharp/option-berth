oberth 为每个 Git worktree 保留一个 Runtime World：这个 checkout 该跑什么、实际启动了什么、操作系统观察到了什么、失败为什么发生。人读 Human 输出，agent 读同一条命令的 --json。

每个 checkout 一个 Runtime World

一个 world 有四个位置。它们不是同一个布尔值的四种视图：每个位置发布不同种类的事实，后面的位置不允许凭空补出前面已经记录过的内容。

Runtime World 的四个位置
位置发布什么边界
Intent服务、端口、depends_on、健康检查和 prepare 步骤。清单由人确认；模型只能起草。
Execution一次运行的启动顺序、实际地址、退出码和日志路径。运行注册表是唯一写入者。
Observation从操作系统读到的进程、监听、健康和退出。没读到的事实保持 unknown。
Causal diagnosis根因、被阻塞的服务，以及脱敏后的 first_error。下游失败不会变成同等原因。

五个站点，一个方向

每条命令都在读写同一条链：worktree → 清单 → 服务 → 运行 → 运行事实。每个站点一个写入者，方向只有一条，没有第二个状态来源。

每一站发布什么，下一站读什么
站点谁写发布什么
worktreeGit，由引擎观察checkout 根路径，以及一次运行所属的 wt_… 身份。
清单人oberth.yaml：服务、端口、依赖、健康检查、引用。
服务启动时的引擎启动的是哪条声明、按什么顺序、落在哪个地址上。
运行运行注册表一个进程的 pid、开始、结束、退出码与日志路径。
运行事实本轮的观察活着、在监听、健康，以及更早那次运行为什么结束。

一条事实链按顺序走完这五个站点，每站一节。

级联失败收敛成一个原因

oberth runtime inspect 读取整个 world。依赖崩溃时，依赖它的服务报成 blocked_by_dep，不算独立失败。诊断指出最先结束的那个进程，并把脱敏后的第一条错误放在旁边。

重启或崩溃循环会被当成证据，而不是一个碰巧很年轻、就算健康的服务。引擎跨代比较启动时间、退出码和日志指纹。

Native Attention

Attention 是引擎内部的确定性观察层。它从运行事实里生成可复核的 note；启用 triage 是另一个决定，一条 note 从不授予杀外部进程或改写清单的权限。

  • strict 只报告事实和证据，不推荐变更动作。
  • assist 在证据足够时给出确切的下一步命令；跑不跑仍由人或 agent 决定。
  • reconcile 显式开启后，仅对归属当前 worktree 的声明服务做有界恢复，永不触碰外部进程、machine: 依赖或清单。

开启 agent hook 后，Attention 在 PostToolUse 工具调用返回时递送 note，agent 不会再多花一轮去调试过期的二进制或已经崩溃的上游。适配器支持 Decisions API、OpenAI 和 Anthropic。oberth attn 显示当前模式、consent 状态和质量账本。

这本指南怎么读

  • 第一次来。先安装 oberth，再跟第一个 worktree走一遍：一个示例项目、五条命令，从一个空 checkout 到一个干净的停止。

两个读者，一个接口

CLI 是唯一的接口。没有第二套 API，没有 MCP server，引擎里也没有模型；--json 是同一份契约换一个程序能读的形状。
