The boundaries are part of the product. These are the questions people and agents ask first, answered the way the product answers them.

Questions people ask first

Does it have a graphical interface?

No. The macOS client is a separate product. It presents the same CLI facts and adds no capability the CLI lacks; it is not a second source of state.

Is it a machine-wide port radar?

No. It answers for this worktree's declared services, not for every socket on the host. machine: dependencies are observed read-only, and an unfiltered stream is only a compatibility view.

Does it write my Git or my manifest?

Git is read-only: no commit, no stage, no branch switch. oberth.yaml is written only by a person's oberth init adopt, and an agent may draft it and do nothing more.

Is “no port” the same as “not running”?

No. A portless worker is observed through its run record. Process, listener, health and exit are four separate facts, and one does not imply another.

How much Windows support is there?

There is a native build and smoke test plus an arm64 cross-build. Full service scenarios are verified on macOS and Linux, and Windows lifecycle claims are not made from those runs.

Does it need a model account or a cloud?

No. The engine runs locally, has no built-in model inference and no cloud sync. The optional model assessment (oberth jev) is off unless a person enables it, and it never enters the control path.

Does it install hooks, an MCP server or the agent skill?

No. Integration means calling the CLI from your own scripts. The product installs no hooks, registers no MCP server, writes no tool configuration and does not install the coding-agent skill.

Can it work with Claude Code, Cursor, Codex or Conductor?

Yes, from their own setup, run and cleanup slots, or from an outer wrapper. The engine modifies none of their configuration, and the recipes are documentation you paste.

What can it delete?

It stops services and reports identities. It never deletes a database, a data directory or a ledger row; that stays a person's call. Uninstall is a separate script, and purging ~/.option-berth requires an explicit flag.
