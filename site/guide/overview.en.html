oberth keeps one Runtime World per Git worktree. It records what the checkout should run, what was actually started, what the operating system reports, and why a failure happened. A person reads the Human output; an agent reads the same command with --json.

A Runtime World per checkout

The world has four positions. They are not four views of one flag: each one publishes a different kind of fact, and a later position is not allowed to invent what an earlier one already recorded.

The four positions of a Runtime World
PositionIt publishesIts boundary
IntentServices, ports, depends_on, health checks and prepare steps.A person confirms the manifest; a model may only draft it.
ExecutionStart order, actual address, exit code and log path for one run.The run registry is the only writer.
ObservationProcess, listener, health and exit, read from the operating system.An unread fact stays unknown.
Causal diagnosisRoot causes, blocked services and a redacted first_error.A downstream failure does not become an equal cause.

Five stations in one direction

Every command reads or writes the same chain: worktree → manifest → service → run → runtime facts. One writer per station, one direction, no second source of state.

What each station publishes and what the next one reads
StationWho writes itWhat it publishes
WorktreeGit, observed by the engineThe checkout root and the wt_… identity a run belongs to.
ManifestA personoberth.yaml: services, ports, dependencies, health checks, references.
ServiceThe engine, at startWhich declaration it started, in which order and on which address.
RunThe run registryThe pid, start, end, exit code and log path of one process.
Runtime factsThis round's observationAlive, listening, healthy, and the reason an earlier run ended.

One chain of facts walks the five stations in order, one section each.

Cascading failures collapse to one cause

oberth runtime inspect reads the whole world. When a dependency crashes, its dependents are reported as blocked_by_dep, not as separate failures. The diagnosis names the process that ended first and keeps the redacted first error next to it.

A restart or crash loop is treated as evidence, not as a healthy service that happens to be young. Start time, exit code and log fingerprint are compared across generations.

Native Attention

Attention is the deterministic observation layer inside the engine. It produces reviewable notes from runtime facts; enabling triage is a separate decision, and a note never grants permission to kill foreign processes or edit manifests.

  • strict reports read-only facts and evidence without recommending mutations.
  • assist gives the exact next command when the evidence supports it; the person or agent still decides whether to run it.
  • reconcile opts into bounded recovery for declared services owned by this worktree, never touching foreign processes, machine: dependencies, or oberth.yaml.

With an agent hook enabled, Attention delivers a note on PostToolUse, when the tool call returns, so the agent does not spend another turn debugging a stale binary or a crashed upstream. The adapter supports the Decisions API, OpenAI and Anthropic. oberth attn shows the current mode, consent state and quality ledger.

  • You are wiring an agent. Start with Facts as JSON, then read Coding agents for the lifecycle calls and the Attention hook.

Two readers, one interface

The CLI is the only interface. There is no second API, no MCP server and no model inside the engine; --json is the same contract in a shape a program can read.

llms.txt lists this guide for machines, and llms-full.txt carries every chapter as plain text.

Scope

The guide explains the chain; the contract lives in docs/cli.md. The homepage shows the product and its workbench. The examples use Hello Worktree because it needs nothing but Python 3; the same chain applies to any stack.
