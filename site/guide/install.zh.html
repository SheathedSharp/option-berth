安装只做三件事：解析最新发布、校验对应平台的压缩包、把二进制放进 PATH。它不碰你的项目，也不启动 Runtime Service。

一行命令，macOS 与 Linux

脚本读取 uname，挑出对应的 darwin 或 linux、amd64 或 arm64 压缩包，核对发布在同一目录下的 .sha256，然后安装。不需要管理员权限。

  • 二进制：~/.local/bin/oberth。
  • 许可证与构建清单：~/.local/share/option-berth。
  • PATH：在你已有的一份 shell 启动文件里加一行。脚本从不新建文件。
  • 运行状态：~/.option-berth，安装脚本既不创建也不修改它。

用 --version v1.0.0 固定版本，用 --dir "$HOME/tools/bin" 装到别处，或用 --no-modify-path 不动 shell 文件。官方主机慢或不可达时，脚本会探测镜像；换源后仍须报告同一个 SHA256，安装才会继续。

Windows

二进制落在 %LOCALAPPDATA%\option-berth\bin，只改当前用户的 PATH。用 -Version 固定版本，用 -NoModifyPath 不动 PATH。替换文件之前，安装脚本会停掉正在运行的 oberth Runtime Service，但不会替你停项目服务。

确认构建

version --json 返回你实际装上的二进制的 version、commit、built 和 platform。doctor 检查清单、Runtime Service、CLI 路径、日志目录，以及当前进程能不能看见监听。看不见时，它报告自己是 blind 并给出下一步，不会写成“没有东西在监听”。

平台支持

完整服务场景只在 macOS 与 Linux 上验证。Windows 有原生构建、冒烟测试和一次 arm64 交叉构建，这不等于那边的服务生命周期被验证过。引擎没有图形界面：macOS 客户端是独立产品，coding agent skill 也是。

升级与卸载

切换到协议 3 前，先用匹配旧后台的已安装 CLI 正常停止旧后台，再运行对应平台的安装命令。协议 3 更名命令与端点且没有旧别名，保留持久数据，并拒绝仍被其他后台拥有的数据库。不要清锁或重置数据强行切换。新后台使用 oberth runtime service run --detach。macOS 与 Linux 用 uninstall.sh 卸载，Windows 用 uninstall.ps1。卸载脚本先停 Runtime Service，默认保留 ~/.option-berth；传 --purge-state 才会一并删除。确切参数与各平台路径见 安装与卸载。

安装脚本不做什么

不启动服务、不写 Git 状态、不需要管理员权限。它不安装 macOS 客户端或 coding agent skill；除了你允许的那一行 PATH，它不动你的 shell。
