The installer does three things: it resolves the latest release, verifies the archive for your platform, and puts the binaries on your PATH. It does not touch your project, and it does not start the daemon.

One line, macOS and Linux

The script reads uname, picks the matching darwin or linux archive for amd64 or arm64, checks the .sha256 file published beside it, and installs. It needs no administrator rights.

  • Binaries: ~/.local/bin/oberth and ~/.local/bin/jev-attention.
  • Licenses and build manifest: ~/.local/share/option-berth.
  • PATH: one line added to a shell startup file you already have. The script never creates a new one.
  • Runtime state: ~/.option-berth, which the installer neither creates nor modifies.

Pass --version v1.0.0 to pin a release, --dir "$HOME/tools/bin" to install somewhere else, or --no-modify-path to leave your shell files alone. When the official host is slow or unreachable, the script probes mirrors, and a mirror has to report the same SHA256 before the install continues.

Windows

The binaries land in %LOCALAPPDATA%\option-berth\bin, and only the current user's PATH changes. Pin a version with -Version, and leave PATH alone with -NoModifyPath. Before it replaces files, the installer stops a running oberth daemon, but it does not stop your services.

Check the build

version --json returns version, commit, built and platform for the binary you actually installed. doctor checks the manifest, the daemon, the CLI path, the log directory, and whether the current process can see listeners. If the listener check cannot run, it reports that it is blind and gives the next step; it never writes “nothing is listening”.

Platform support

Full service scenarios are verified on macOS and Linux. Windows gets a native build, a smoke test and an arm64 cross-build, which is not the same as a verified service lifecycle there. The engine has no graphical interface: the macOS client is a separate product, and the coding-agent skill is another one.

Upgrade and uninstall

Rerun the installer for your platform to upgrade. Afterwards, run oberth daemon stop once and the next call starts the new build. On macOS and Linux, uninstall with uninstall.sh; on Windows, use uninstall.ps1. The uninstaller stops the daemon first and keeps ~/.option-berth unless you pass --purge-state. The exact flags and per-platform paths are in Install and uninstall.

What the installer will not do

It starts no service, writes no Git state and needs no administrator rights. It does not install the macOS client or the coding-agent skill, and apart from the PATH line you allow, it leaves your shell alone.
