接口只有 CLI 和 --json。集成就是在工具自己的 setup、run、cleanup 槽位里调用它。Native Attention 可以在 agent 的工具调用返回时加一条中途 note。产品不替你装 hooks，也不代你写任何配置。

三个生命周期调用

工具提供生命周期槽位时，用同样的三次调用：创建之后启动，运行期间读取，结束时停止。

agent 开局的读取

oberth --help 末尾有一段 For agents，给的是阅读模式，不是新命令。几次读取足够让会话定位自己，不用去拼 ps、lsof 或 tail。

  • 先 status：声明了什么、跑着什么、在哪个端口、健康过没过、最近为什么失败。
  • 确实应该有东西在跑时才 up --wait。它等真实就绪，而不是睡一会儿。
  • 失败之后才 logs --run current --first-error。它指向一行，不给猜测。

从 Runtime World 开始

oberth runtime inspect --json 用一个值返回整个 world：intent、execution、observation 和 diagnosis.root_causes。agent 在第一条命令之前读它，就不必从 shell 历史里重建这套服务栈。

把两次读取分开用。runtime inspect 是诊断用的完整记录；status --brief 是 agent 可以反复读、不会挤爆上下文的短读。

一轮工作里的 Native Attention

Attention 需要显式启用。oberth attn status 报告模式和 consent 状态；oberth attn on 打开本机 consent；oberth attn assess 为一个任务跑一次有界评估。确定性的 note 不需要任何模型调用。

三档 triage 模式是 strict、assist 和 reconcile。启用项目 hook 后，PostToolUse 会在工具调用返回时递送一条新的 note，agent 可以在调试错二进制之前先重启过期服务。适配器支持 Decisions API、OpenAI 和 Anthropic。建议不授予权限；有副作用的动作仍由人决定。

接入配方

工具自己的配置由用户写。项目级配置可以随仓库提交，但产品不分发集成代码，也不写任何工具配置。

hook 里容易踩的坑

  • hook 通常不加载你的 shell rc。用 oberth 的绝对路径，或显式设置 PATH；node、npm、python3 也必须能找到。
  • workspace 根不一定是 Git checkout 根。先 cd "$(git rev-parse --show-toplevel)"，再把同一个根传给 down --worktree。
  • 不要给 port: auto 的服务硬编码 PORT。服务自己的 env: PORT 会覆盖注入值，让等待盯着错的端口。
  • 优先打开框架的严格端口选项。悄悄换端口的框架会把冲突拖成迟到的 ready_timeout。
  • 沙箱里观察可能是盲的。不要在循环里反复重开；跟着 observation_* 的 hint 换到沙箱外重试。

skill 是独立产品

option-berth-skill 教 agent 同一套 CLI 和同样的 --json 形状。它单独安装，例如 npx skills add SheathedSharp/option-berth-skill -g。引擎不安装、不更新、也不依赖它；装不装是用户的决定。
