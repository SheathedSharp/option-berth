失败会留下日志、退出码和原因。logs 读服务自己的输出和它所属的那次运行，而不是重新拼一条 shell 管道。

读一次，或持续跟随

按服务名读，端口形式仍然可用。--once 读一次就退出。不带它时，logs 打印最近的行并继续跟随。--lines N 限制一次读取的行数，跟随模式写 NDJSON，一行一个值。

  • 有监听的服务读那个进程的日志。无端口 worker 读它那次运行的服务日志文件。
  • 日志文件跨运行追加。--run current 只读当前运行那一段，从记录下来的偏移开始。
  • --json --once 返回一个文档，带 source、lines、truncated、service、run_id、pid 和 status。

你真正需要的那条失败

--run current --first-error 读当前运行，从固定词表里找第一条匹配的行：error、exception、fatal、panic、traceback，不区分大小写。它返回行号和原始文本。这是一个位置，不是根因判断；什么都不匹配时，JSON 写 no_first_error。

文档会加上 log_offset、可选的 run_start_unknown，以及带 line 和 text 的 first_error，或 no_first_error。如果日志已经轮转、记录偏移越过了文件末尾，读取会退回文件开头并置上 run_start_unknown，让你知道这次的行可能包含更早的运行。

无端口 worker 也有日志

没有监听的 worker 不是没有输出的服务。oberth logs worker --once 读那次运行的服务日志文件，状态和偏移由运行记录提供。

它不做什么

  • 它不读另一个 checkout 的服务。名字在本 worktree 的清单里解析。
  • --first-error 找的是一个位置。它不判定原因，也不隐藏周围的上下文行。
  • 它不凭空补一次启动。没有偏移的运行记录返回 not_found，并建议把服务重启一次；--run 还需要 daemon。
