The interface is the CLI and --json. Integration means calling it from the tool's own setup, run and cleanup slots. The product installs no hooks for you, runs no MCP server, and writes no configuration on your behalf.

Three moments

Where a tool offers lifecycle slots, use the same three calls: start after the checkout is created, read while it runs, and stop at the end.

The reads an agent opens with

oberth --help ends with a For agents section that gives a reading pattern, not new commands. Three reads are enough for a session to orient itself without assembling ps, lsof or tail.

  • status first: what is declared, what runs, on which port, whether health passed, and why it last failed.
  • up --wait only when something should be running. It waits for real readiness instead of a sleep.
  • logs --run current --first-error only after a failure. It points at a line, not a guess.

Recipes

Users write the tool's own configuration. Project-level configuration can be committed, but the product distributes no integration code and writes no tool configuration.

The most portable integration is a paragraph in AGENTS.md or CLAUDE.md. This is a compact version; the full section, including the machine: and workspace: boundary, is in docs/integrations.md. The engine does not install it.

Pitfalls

  • Hooks often do not load your shell rc. Use the absolute path to oberth, or set PATH explicitly; node, npm and python3 have to be on it too.
  • The workspace root is not always the Git checkout root. Run cd "$(git rev-parse --show-toplevel)" first, and pass the same root to down --worktree.
  • Do not hardcode PORT for a port: auto service. The service's own env: PORT overrides the injected value and makes the wait watch the wrong port.
  • Prefer the framework's strict-port option. A framework that quietly switches ports turns a conflict into a late ready_timeout.
  • In a sandbox, observation may be blind. Do not retry the same start in a loop; follow the observation_* hint and retry outside the sandbox.

The skill is a separate product

option-berth-skill teaches an agent the same CLI and the same --json shapes. It is installed separately, for example with npx skills add SheathedSharp/option-berth-skill -g. The engine does not install, update or require it; whether to install it is the user's decision.
