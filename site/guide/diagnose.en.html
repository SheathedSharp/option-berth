Most confusion about a local stack is a missing fact, not a broken service. This page routes a symptom to the one command that produces the missing fact, and then to the chapter that explains it.

Start with the read

oberth status is the first command for almost every symptom: it prints the manifest, the runs and the observed runtime facts side by side. If it prints a failure reason, read that reason before reading any log — it names the service and the phase.

What to keep when you ask for help

  • The exact command and its exit code, not a paraphrase of what it printed.
  • oberth status --json from the same checkout, so the reader sees the same facts.
  • The first error of the current run: oberth logs <service> --once --first-error.
  • What the observer said, if observation appeared at all: which code, and from which kind of process.

What is not a fix

Raising a timeout, killing a pid by hand or starting the service outside oberth all make the symptom disappear while leaving the fact unread. The next session inherits the same unknown, one more layer deep. Read the reason first; change the manifest second.
