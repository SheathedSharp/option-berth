边界也是产品的一部分。这些是人和 agent 最先会问的问题，按产品的回答方式写。

最先被问的问题

它有图形界面吗？

没有。macOS 客户端是独立产品。它呈现同一份 CLI 事实，不增加 CLI 没有的能力；它不是第二个状态来源。

它是整机端口表吗？

不是。它只回答这个 worktree 声明的服务，不回答主机上的每个 socket。machine: 依赖只读观察，未过滤的流只是兼容视图。

它会写我的 Git 或清单吗？

Git 只读：不提交、不暂存、不切分支。oberth.yaml 只由人的 oberth init adopt 写入；agent 最多只能起草。

“没有端口”等于“没在运行”吗？

不等于。无端口 worker 通过运行记录观察。进程、监听、健康、退出是四种独立事实，一种推不出另一种。

Windows 支持到什么程度？

有原生构建、冒烟测试和一次 arm64 交叉构建。完整服务场景只在 macOS 与 Linux 验证；不从那些运行里推断 Windows 生命周期。

需要模型账号或云端吗？

不需要。引擎本地运行，没有内置模型推理，也没有云端同步。可选的模型评估（oberth jev）默认关闭，除非人主动启用，而且永远不进入控制路径。

它会装 hooks、MCP server 或 agent skill 吗？

不会。集成就是在你自己的脚本里调用 CLI。产品不装 hooks、不注册 MCP server、不写工具配置，也不安装coding agent skill。

能跟 Claude Code、Cursor、Codex、Conductor 一起用吗？

能，在它们自己的 setup、run、cleanup 槽位或外层 wrapper 里调用。引擎不改它们的任何配置，配方是给你粘贴的文档。

它会删掉什么？

它停止服务、报告身份。它从不删除数据库、数据目录或账本行；那是人的决定。卸载是独立脚本，清空 ~/.option-berth 需要显式参数。

机器入口

  • llms.txt——指南与契约的精选索引，每条链接一行说明。
  • llms-full.txt——全部英文章节合在一个纯文本文件里。
  • sitemap.xml——两种语言的每个页面。

HTML 页面是源；机器文件在构建时从同一份内容生成，所以它们不会悄悄和书脱节。
