# 文档维护

页面职责和双语格式以 [docs/AGENTS.md](../../../docs/AGENTS.md) 为准；本 skill 只说明改动时怎么做，不另建规范副本。

## 步骤

1. **先确认变化。** 核对真实代码和命令 help 定义，说明读者操作或输出哪里变了。逐项判断 README 入口、操作页、[CLI reference](../../../docs/cli.md)、[examples](../../../examples)、项目 skill 是否受影响，只改相关内容；无文档影响时简述理由，不凑改动。
2. **找现有位置。** README 只放产品边界、最短上手和任务导航；细节沿 [docs 索引](../../../docs/index.md) 按读者任务、主题放回现有页。不要为一个功能造一组重复页面，也不放实现日志、方案卡或架构黑话。
3. **写给读者。** 中文自然清楚，必要术语先解释；英文自然表达，同步事实、命令和导航，不硬译。删赘述不等于删现行字段、约束、验收合同；生成文档应改源后生成，不能只修生成物。
4. **处理退出的内容。** 当前说明与历史记录分开，旧测试结果不当当前验收；删除功能时清掉活跃入口和引用。Sonar 等已移除的历史源码、声明不因“过去有过”而恢复，真实旧记录留在 Git 历史或既有历史区。
5. **按实际材料维护归属。** 只有组件变化涉及第三方时才核 [third_party/README.md](../../../third_party/README.md)：以实际使用或分发的代码、依赖、工具为据，沿现有结构保留必要固定版本完整源、原 LICENSE/NOTICE 和简明来源、版本、本地修改记录。移除组件先核实际引用，不凭历史补归档，也不无依据删必要许可；不重建根 `THIRD_PARTY_NOTICES.md`。
6. **做相称的验证。** 用现有工具与人工复核检查链接、锚点、示例、双语和许可分发；涉及双语页可运行 `python3 scripts/check_docs.py`，其他检查按 [开发入口](../../../docs/agent/develop.md) 选取，不每次全跑。scripts 少而精，不新增专用校验脚本、机器锁清单、自动管理框架或 CI 门禁，不把维护文档变成开发前置枷锁；也不删除或改弱现有安全门。

## 完成前

- 看 `git diff --check` 和实际差异：入口能到正确现有页，事实与实现一致，中英文都已按影响更新；没有影响的范围已说明。
- 需要保留的合同、许可和打包输入没有丢；不复制另一份权威规范，不恢复已撤材料。
- 只报告实际检查和未验边界；文档验证不运行真实用户服务、模型、危险 TestMain 或全仓产品测试，不为看源码运行第三方脚本。
