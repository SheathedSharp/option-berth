# 常见问题

[English](troubleshooting.md) | 中文

## 先保留证据

在出问题的工作树里运行 `oberth doctor`，再看 `oberth status --json`。保留错误码、选中的工作树和相关服务日志。准备分享前，去掉凭证、环境变量的值和私人路径。`oberth feedback report` 可以准备反馈；收集和提交行为先看[命令参考](cli.zh.md#oberth-feedback)。

## 按现象排查

| 现象 | 先看什么 | 安全的下一步 |
| --- | --- | --- |
| 连接不到后台 | 后台状态和后台自己的日志 | 按[后台服务说明](runtime-service.zh.md)判断；没运行不等于崩溃 |
| 观察结果为 blind 或 partial | 在报错环境运行 `doctor --only listener_observation` | 换普通终端重试；看不见不代表端口空闲 |
| 固定端口被占用 | 服务错误，以及存在时的 `last_exit.port_holder` | 先确定归属；不要终止无关进程，也不要偷偷改端口 |
| `up --wait` 超时 | 服务日志、依赖与健康检查 | 修真正的就绪问题；仅有 PID 不够 |
| 后台任务没有监听端口 | 它的运行与退出字段 | 支持无端口任务，不能据此判断已经停止 |
| 返回 `runtime_service_busy` | 匹配的后台与数据库拥有者 | 通过拥有者读取；切版本前先正常停止旧后台 |
| 组名或身份选择有歧义 | `worktrees --json` 和精确项目路径 | 指定工作树或身份，不要操作所有同名项 |
| 没有更新提示 | PATH 指向的安装、版本及 `version --check` | 自动提示不保证每次出现；显式检查不会执行安装 |

## 只报告有证据的结论

不要为了收集报告就执行 `doctor --fix`、替换二进制、重置状态或重启用户服务。观察失败不等于系统里什么都没有。编译通过、合成测试通过也不等于平台完整验收；区别见[验证范围](agent/validation.md)。
