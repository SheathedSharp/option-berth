# oberth 负责什么

[English](product.md) | 中文

`oberth` 管理 Git 工作树里的本地服务，并观察它们的运行状态。人和编程助手使用同一套 CLI/JSON，不必各自猜测哪个进程属于哪个项目目录。想先用起来，读[快速开始](quickstart.zh.md)；要查精确行为，读[接口参考](cli.zh.md)。

## 它管理哪些对象

| 对象 | 含义 | 谁说了算 |
| --- | --- | --- |
| 工作树 | 一份项目检出目录及其 Git 身份 | 代码和文件系统观察 |
| 配置文件 | `oberth.yaml`，声明要运行什么 | 人审阅后采用 |
| 服务 | 启动命令、依赖、可选端口和就绪检查 | 配置文件 |
| 某次运行 | 一次具体启动，包含身份、PID、起止和日志 | 运行引擎记录 |
| 运行状态 | 观察到的进程、监听、健康、退出和变化 | 确定性代码，不靠模型推断 |
| 工作记录 | 临时任务及其观察到的结果 | 显式命令与退出记录 |

进程活着、端口开始监听、应用健康是三件事。观察缺失表示未知，不表示一定不存在。每次运行都有工作树归属和代际；迟到的观察不能套到替代它的新进程上。

## 可以拿它做什么

声明服务，按依赖顺序启动，等待就绪，读日志，并只停止所选工作树的运行。自动端口是一种预留，不代表可以抢占已被占用的固定端口。没有监听端口的后台任务也是服务。目录删除后仍可用已记录的身份定位；不会自动删除应用数据。

“Oberth Runtime”是这部分运行管理职责的名称；“Runtime Service”是负责运行注册、观察和存储的本地后台进程。它不是第二个产品，也不是项目里的一个服务，见[后台服务](runtime-service.zh.md)。

## 谁可以修改什么

| 操作 | 边界 |
| --- | --- |
| 修改配置文件 | 由人确认；助手可以起草，起草不等于批准采用 |
| 启动、停止、重启 | 只针对选中的已声明服务或明确点名的底层目标；发信号前验证身份 |
| 观察 `machine:` 依赖 | 只读，不加入项目的启停目标 |
| 读取 `workspace:` 地址 | 必须明确关联；引用地址不授予启停权 |
| 获取 Git 上下文 | 产品自身的 Git 操作只读 |
| 使用模型 | 可选建议，需要单独同意；不是启停服务的前提 |
| 发送反馈 | 可选，遵守说明的收集与脱敏范围 |

取消、失败和部分完成必须分清。停止请求成功不等于进程已经退出；失败要保留逐项结果。恢复记录先验证，再发布。实现边界在[架构文档](agent/architecture.md)维护，不另外缓存一份状态来绕过失败。

## 编程助手与其他界面

给人看的 CLI 输出和 JSON 描述同一份状态。编程助手从[独立 skill](https://github.com/SheathedSharp/option-berth-skill)学习操作规则；编排工具按[接入指南](integrations.zh.md)显式调用 setup/run/cleanup 命令。oberth 不替它们安装 hooks、注册 MCP 或修改设置。

外部编程助手的登录、模型、审批、工具执行和会话恢复仍由对方负责。消息通过精确参数或原生终端输入传递，不隐藏拼接 shell 命令。结构化流桥只转交审批请求，不自动批准、不放宽权限，也不恢复另一份工作树的最近会话。当前可用 provider 看 `agent list --json`，不以一份静态宣传名单作保证。

## 不承诺什么

这里没有操作系统级隔离：服务命令使用当前用户权限，仍可能访问共享文件、数据库和容器。它不是生产调度器、远程主机管理器、公网端口分享服务、全机雷达或自主清理程序。独立的 macOS 界面展示同样的状态，不能另立一份权威。

可选的 [Attention](attention.zh.md)可以辅助判断某个异常与当前任务是否相关，但不能确定进程真相，也不能授权副作用。没有密钥、网络或模型，引擎仍可使用。[待办](backlog.zh.md)和[验证范围](agent/validation.md)把承诺限制在已经取得的证据内。
