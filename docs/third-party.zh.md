# 第三方源码与许可

[English](third-party.md) | 中文

这个仓库确实使用了第三方软件：Go 依赖库、站点中复制的 GSAP，以及站点开发用的 Playwright。应该留下的是这些源码和必要声明，不是再加一套源码管理框架。

## 仓库里存了什么

| 材料 | 位置 | 用途 |
|---|---|---|
| 版本、官方来源与本地修改记录 | [源码目录](../third_party/README.md) | 人工可读的清单，不是额外开发门禁 |
| 完整源码包 | [sources/](../third_party/sources/) | 固定版本的上游源码，供查看和继续开发 |
| 原始许可文本 | [licenses/](../third_party/licenses/) | 方便直接阅读；原文件也完整保留在源码包里 |
| 分发责任 | [第三方声明](../third_party/README.md) | 版权归属，以及原有二进制发布的许可边界 |

## 范围和“完整”的含义

归档覆盖引擎 Go 模块图选中的全部 59 个模块，包括间接依赖和选中的测试、工具模块；另有原始 SQLite、GSAP、Playwright，以及声明版本的 Go 和构建工具源码。目录逐项记录准确版本与官方 tag 或 commit，所有快照都未作本地修改。

模块 ZIP 是对应版本的完整模块，不是整个上游仓库。保留的 24 份模块 ZIP 是完整上游包的补充；其余选中模块也都有完整上游源码。JSONSchema 的测试套件子模块按固定 commit 单独补齐，没有跟随移动的 main。

这里不是整台 CI 机器的复制品。工具源码快照不表示归档了每个工具独立开发的整个生态。操作系统 SDK、托管 Actions、浏览器二进制、外部 agent 和模型服务仍属于环境前提。上游自带的 vendor、测试资产和各自许可原样留在源码包中。

## 怎样查看或更新

从目录选版本，先查看包内文件，再用支持路径、链接安全过滤的工具解压到本工作树之外的新目录。nfpm 原始测试夹具 `files/testdata/tree/symlinks/link1` 指向 `/etc/foo`，这里仅把它保留为数据，不解压、不执行。只是看源码，不需要运行安装钩子或测试。

有意升级时，取得对应的官方源码，保留 LICENSE、NOTICE 和版权头，再更新目录中的版本、来源、本地修改说明即可。不必维护专用下载器、哈希锁、清单一致性检查或自动更新器。收集时的来源核对是一次性工作，不成为产品开发的新前置依赖。

这些归档不参与 vendor 构建。Go 仍按未改动的 `engine/go.mod`、`engine/go.sum` 解析依赖。原有产品测试、模块校验和二进制发布检查继续保留；撤掉额外脚本，不等于撤掉这些安全保障。

## 许可和历史来源如何处理

GSAP 使用自己的标准“不收费”许可，不适用本项目的 MIT，也不能擅自认定为 OSI 开源许可。原始文件头、官方许可网页快照和方便阅读的正文都已保留。历史来源的旧记录留在 Git 历史中，不重新作为当前依赖归档。

项目根许可不替代上游或嵌入子树的条款。仍适用的声明要保留；来源不明就记不确定，不替它编造许可。
