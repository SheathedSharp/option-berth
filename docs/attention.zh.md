# 可选的模型建议：Attention

[English](attention.md) | 中文

Attention 帮助编程助手判断：已经发现的运行异常是否影响当前任务、是否值得请人选择下一步。它不负责确定进程状态、不运行命令、不修服务，也不授予操作权限。不启用它，`status`、`up`、`down` 仍然可用。

## 先查看，再决定是否启用

下面的操作不会调用模型服务：

```sh
oberth attn status
oberth attn assess --dry-run
```

`status` 显示实际生效的配置和同意状态，不显示密钥。`assess --dry-run` 展示脱敏后的请求。请先检查这份内容，再决定是否允许把运行信息发出本机；有脱敏不等于可以不审阅任务文本。

结构化编码任务可由现有 agent stream 根据明确的运行范围自动附着观察，再通过有界的原生反馈轮次把相关证据交回助手。调用方只需在任务入口提供一次范围，不应让人自己维护长串 `assess --follow` 命令。直接启动的助手仍是另一条路径：`on` 和已安装的 skill 都不能证明已附着。范围、结束和反馈边界见 [stream 任务合同](cli.zh.md#oberth-agent-stream)。

## 配置和同意是两步

只有决定配置模型服务后，才运行下面的命令。`config` 会依次询问服务商、模型和隐藏输入的密钥，然后先发一次合成请求，成功后才保存仅当前用户可读的设置。合成请求不含工作树信息，但仍会连接服务商，也可能产生费用。探测失败不会覆盖原有设置。仅完成配置不会启用真实评估。

```sh
oberth attn config
oberth attn on
```

`on` 表示本地同意启用，不等于允许助手重启服务或发送无关数据。`BERTH_ATTN_KEY`、endpoint、model 环境设置只提供配置，不表示同意。显式的进程级开关 `BERTH_ATTN=1` 与持久化 `enabled` 的优先级见[适配器参考](agent/attn-adapter.md#an-environment-key-is-a-secret-not-consent)。

不要把密钥放进命令参数、Git、任务上下文 JSON、服务日志或反馈里。无人值守配置先看 `attn config --help` 中的标准输入或环境变量方式，不把密钥复制进 shell 历史。模型名或 endpoint 预设只是填写便利，不保证你的账号有访问权。

## 哪些信息可能离开本机

符合条件的请求包含有长度限制的事件摘要、哈希化的工作树身份、有限的分支与任务文本、状态修订、证据引用，以及已授权的固定选项 ID。不包含完整日志、环境变量的值、密钥或无关工作树。请检查实际 dry-run 输出，不要只凭假想示例判断。

任务上下文必须明确授权允许的选项集合。异常记录里的选项只是候选，不是授权。模型返回值必须符合这个词表，不能生成 shell 命令，也不能扩大权限。建议涉及副作用时，仍需人决定。

## 失败不代表可以越权继续

缺密钥、拒绝请求、限流、网络故障、超时、答复格式错误或状态过期，都不会妨碍只读运行状态的路径。助手应说明缺少建议的原因，必要时直接问人。迟到的评估在使用前要与最新状态核对。概率没有经过校准的保证，也不是安全承诺。

事件连接只安排符合条件的状态读取，不是新增全局监听器，也不保证每个事件都调用模型。follow/subscribe 模式属于当前任务及其允许范围，不代表所有项目。实现、固定原因码与本地质量记录见[适配器参考](agent/attn-adapter.md)。

## 关闭

下面两条是不同选择：第一条关闭评估，第二条同时忘记已保存的密钥。它们都不会连接模型服务。

```sh
oberth attn off
oberth attn off --forget
```

关闭建议不会删除底层运行记录，也不会改变服务启停。本地质量记录不会自动上传；准备分享前，先看适配器参考中的内容范围。
