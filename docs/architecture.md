# 当前架构与支持边界

产品定义以 [product.md](product.md) 为准，用户接口以 [cli.md](cli.md) 为准。
本文解释当前生产实现，不把历史决策、临时排障或研究任务当成永久要求。

## 一条事实链

`worktree → manifest → service → run → runtime facts`

| 环节 | 生产职责 | 必须守住的边界 |
|---|---|---|
| 服务事实 | `servicefacts` 纯归约；`runsreg` 提供一次捕获；`groups` 发布适配 | 不做模型判断，不持久化第二份运行真相；登记运行不等于监听就绪。`port_holder` 是运行退出事实与同一次监听批次的读取时连接，只覆盖失败服务自己的端口，不落库、不是第二状态源；缺省表示没观察到，不是端口空闲。 |
| 采集 | `ports` 调用本机成熟适配，解析监听与进程身份 | 失败、取消和带诊断的不完整扫描不能变成“已空闲”；缺身份不能扩大停止目标。 |
| 归因 | `groups` 按本轮路径观察、清单内容索引和运行身份归属 | 同仓库不同 worktree 不串服务；路径缺失、清单失效与未知事实不能冒充确定归属。 |
| 生命周期 | `groupstart` 按依赖起服务；`killer` 校验身份后发信号；注册表记录退出 | prepare 失败不启动；只有上次成功且 `prepare_inputs` 内容未变才跳过 prepare；取消回收自己创建的工作；信号成功不等于退出。 |
| 调度 | `scanner` 统一观察、失效、统计和有序发布 | 旧结果不覆盖新事实；取消不是成功；快照不可变，续接保留有界；健康检查（HTTP/TCP/命令）的失败与超时都不是就绪。 |
| 持久化 | `store` 的 SQLite 事务；`runs` 兼容镜像与恢复 | 必需恢复失败阻止服务；按运行代际更新；不吞掉写失败，不声称能够撤销 OS 副作用。 |

核心由本项目需求驱动；数据库、系统调用和平台适配可以保留成熟实现，不为“自研比例”重写。
来源与版权独立保留在 [engine/UPSTREAM.md](../engine/UPSTREAM.md) 和许可证中。

worktree 的结束端也挂在这条链上：`${worktree}` 来自 checkout 根路径，daemon 把
`身份 → 根路径 → 最近组名/claim key` 记进 `worktree_identities`（迁移 010）。它是身份账本，
不是第二份运行事实：行在目录消失后保留，`exists` 由读取方按文件系统判断；`status` 只发布
当前身份，`worktrees` 只读枚举，`down --worktree/--identity` 才使用账本里的组名停止和交还
预留。删除数据仍由人完成。

## 只读地址与共享环境

`workspace:` 引用和 `machine:` 一样不产生新的运行事实：地址只从对方清单的声明和 daemon 已发布的
运行事实（`state.snapshot` 与 run 登记）解析，解析失败就让使用它的服务启动失败，不回退到字面量或
另一份缓存。`up` / `down` / `restart` 的目标集合仍只来自本清单的 `services:`，引用不扩大它。

`oberth start` 的地址展开复用同一份清单与同一份运行快照；它只改写命令参数，不替命令注入环境，
也不写入新的状态。`env_file:` 在每次启动（含 `prepare:`）前读取，内容不进入状态、日志或
`spec_hash`，读取失败阻止该服务启动。两者都遵守「一条事实链」：不另立状态源，也不缓存第二份
运行结果来绕过失败路径。

## 工作记录

`workplace` 是交接层的能力：agent 可以读回「在这个 worktree 上做过什么、结果如何」来接手，
也可以把引擎看不见的尝试自己写进去。它挂在 worktree 上，不在服务链上，不参与服务事实的归约，
也不被 `status` 当成运行真相。实现在 `internal/workplace`（规则、选择器与 RPC）、
`internal/store/workplaces.go`（行与迁移 009）和 `cmd/workplace*`（CLI 与记录接线）。

- **写入只有一个所有者。** daemon 是账本的唯一写者；CLI 的读路径在 daemon 不在时只读打开同一份
  数据库，写命令走 RPC。工作记录不为自己去启动 daemon。
- **block 只在引擎确实观察到结束时收尾。** 附加的 `oberth start` 由等待它的进程收尾；非附加运行
  由 daemon 在记录该 Run 的退出时收尾（`daemon.OnRunExit`，在注册表锁之外通知）；`agent stream`
  按桥收到的 `turn.completed` outcome 收尾。没有结束证据的条目保持 `running`，不冒充成功。
- **同一个 id 的第二次观察是更新，不是第二条。** 已记下的结果不会被后来的 `running` 覆盖，空字段
  不清空已写的内容，所以一次工作的开始与结束可以任意顺序到达；`seq` 由第一次观察决定。
- **不复制日志。** 引擎记录的 block 只有 `run_id` 与 `log_path`；只有前端上报（`source: reported`）
  的 block 带文本输出，并且明确标成上报方的话，不是引擎的证据。
- **记录失败是诊断，不是命令失败。** 记录在 `start` 与 `agent stream` 之外异步落地，失败在 stderr
  说明一次；队列满时丢弃并说明，因为悄悄漏记的记录读起来和完整的一样。

## 起停与端口预留

启动只接受当前服务的就绪证据。无端口运行的 ID/PID/StartedAt 和停止回执在首次信号
之前固定，不在后续阶段通过同一个 PID 重新选择进程。缺少可靠控制身份时拒绝操作。

`down` 在信号前捕获预留；实际停止后复用新扫描，检查原始注册表（包括兼容 stopping
记录），并在短事务中比较完整预留集合后删除。失败、取消、部分停止、仍有运行/监听或
预留变化时保留并明确报错。空目标分支同样检查，不用 not_found 或 envelope.OK 代替证据。

同一 Store 的常量大小 revision 使旧释放观察失效；最终事务比较防止删除已经变化的行。
不维持每个历史任务一份状态。停止期间不持有数据库事务或 claims 锁；最终写入按
claimsMu → runtime.runsMu 读锁 → registry.mirrorMu → Store.wmu 排序，元数据 mu 不跨 IO。
锁冲突保留并提示重新观察重试。回调不得重入扫描器、claims manager 或注册表写入。

## 本次支持范围

维护目标是本机开发服务，macOS 为主要使用环境，Linux 为引擎验证环境。Windows 在托管 runner 验证 x64 原生构建、CLI 冒烟和事实/持久化测试，并交叉构建 arm64；
不将这些检查等同于全部服务起停或 GUI 的 Windows 验收。

每个 BERTH_HOME 使用一个受 daemon 锁管理的写入实例；升级时先停止旧实例。不支持
不遵守锁协议的旧写者、多个 daemon 强行共享账本或外部直接写数据库；这些不是首次合并
必须扩展出的功能。兼容代码不得以“旧写者任意并写安全”宣传。

支持普通 checkout、常规 linked worktree 和显式清单路径。任意裸仓库/common-dir/
隔离 Git 目录不是本轮承诺；遇到无法确认的归属应保留未知、拒绝危险控制，不能猜测。
平台权限决定进程证据的可见范围，不做整机进程雷达，也不提权以观察其他用户。

OS 观察与数据库提交不是原子事务，外部进程可在观察后变化。数值 PID 信号仍有系统级
竞争窗口；同步文件系统、平台调用与数据库驱动中的在途 IO 不保证可被 context 硬中断。
这些是需明示的边界，不是通过无限追加 worker、缓存和锁来制造的保证。

## 验证原则

当前输入的编译、测试和真实起停结果见 [validation.md](validation.md)。误停、串 worktree、
账本损坏和自有进程残留必须修复，不能通过性能收益抵消。没有重复同输入测量就不宣称
整体加速或无泄漏。长期使用、attention 质量评估和研究性性能对照属于后续迭代，
不以一周使用或任意初始百分比阈值阻止首次源码发布。
